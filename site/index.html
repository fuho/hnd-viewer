What the live view looks like

A factory-sealed HND-NE3 camera boots its own Wi-Fi access point and streams a ~12 fps 480×480 JPEG image plus sensor data. The app renders it with a gyro roll overlay.

What it does

Everything the vendor app did — none of the baggage

The camera ships sealed with its own Wi-Fi hotspot. hnd-viewer talks to it directly, so there is no vendor app, no account, and no cloud in the loop.

  • Discover & connect

    Finds the camera’s Wi-Fi access point (SSID HNDEC_55-…) and joins it. Gateway 192.168.1.1 — no IP hunting, no config file.

  • Live 480×480 video

    Watch the JPEG stream in real time with rotation, mirror, and brightness controls.

  • Gyro roll overlay

    Reads the camera’s own 3-axis accelerometer over UDP and draws its roll orientation on top of the video.

  • Snapshot to gallery

    Save any frame to the device photo library with one tap.

  • MP4 recording In progress

    The FFmpeg-based writer is done; wiring the Record button into the UI is in progress.

  • Offline & open

    The camera AP has no internet and the app needs none: raw UDP only, zero cloud, and source you can read and audit.

Why not a web page?

The camera runs no HTTP server — everything is raw UDP on fixed ports, and browsers can’t open UDP sockets. That is exactly why this is a native app on your phone or laptop, and why it works on a plane: no internet required at any point.

Under the hood

How it talks to the camera

The HND-NE3-D (Beken BK7231) exposes no web interface — a small set of raw UDP datagrams controls everything. The wire format was reverse-engineered and re-implemented from scratch for this project; it carries no vendor code.

  1. 1

    The camera is its own network

    It boots a Wi-Fi access point (HNDEC_55-…) with gateway 192.168.1.1. The viewer joins that AP as a DHCP client — no internet is needed or provided.

  2. 2

    Discover & wake

    The viewer broadcasts the 4-byte datagram 66 30 01 01 to 192.168.1.255:46526; the camera answers with a JSON identity document. Discovery is optional — the stream address is fixed, so the app can skip straight to video.

  3. 3

    Start the video

    Sending 20 36 to 192.168.1.1:44506 starts the stream. Frames arrive as 480×480 JPEG fragments that are reassembled over 3 rotating buffers × 40 slots before decoding.

  4. 4

    Subscribe to the gyro

    86 06 01 to 192.168.1.1:52219 turns on 3-axis accelerometer telemetry, which the app renders as a roll overlay.

  5. 5

    Render, snapshot, record

    Everything downstream is plain Flutter: decode and paint each frame, overlay the orientation, snap to the gallery, or write MP4 via the FFmpeg writer.

Getting started

Build it yourself

The full development guide lives in the repository README. The short version:

Prerequisites

  • Flutter SDK (stable channel)
  • Android: JDK 17 plus an Android SDK with the android-36 platform, an NDK, and build-tools (debug keystore is committed, so flutter build apk is hermetic)
  • macOS / iOS: a full Xcode install
git clone https://github.com/OWNER/hnd-viewer.git   # replace OWNER with the real owner
cd hnd-viewer
flutter pub get
flutter test                # protocol unit tests — no device needed
flutter run                 # live view on a connected device
flutter build apk --debug   # Android debug APK

Prefer binaries? Grab the latest release instead.
